Business Summary

Core Structure BARE by Marlese runs through a website-led client flow. The website files are managed in GitHub and served through Cloudflare. DNS, Pages/Workers, the /api booking system, D1 database, consultation processing, rescheduling, cancellations and reminders are all handled through Cloudflare. Emails are sent through Resend, payments are taken through Stripe, and appointments are stored in Cloudflare D1 through your own booking API.

Keep the client journey simple and premium: complete the consultation first, receive confirmation, move to the deposit page, pay the £30 deposit through Stripe, return automatically to the unlocked Cloudflare/GitHub booking page, choose an available appointment, and receive manage/cancel links by email.

Current Booking, Payment & Appointment Management Flow

Consultation Booking

  • consultation.html submits to the Consultation Worker
  • deposit.html handles the £30 Stripe deposit step
  • Stripe success URL redirects to booking.html?session_id={CHECKOUT_SESSION_ID}
  • booking.html unlocks after the session_id is detected
  • /api returns available consultation slots and saves the confirmed booking

Reschedule & Cancel

  • reschedule.html loads booking details using id and token
  • /api?reschedule=update validates the token, slot and booking status
  • cancel.html loads booking details using id and token
  • /api?cancel=confirm changes the booking status to cancelled
  • You and the client receive amendment or cancellation emails

Reminders & Status

  • Appointments start as status: confirmed
  • Cancelled appointments become status: cancelled
  • The scheduled reminder Worker sends reminders 23–25 hours before confirmed appointments
  • reminder_sent changes from no to yes after the reminder is sent
  • Past confirmed bookings are marked as completed automatically
Key redirect rules
Consultation deposit success must redirect to booking.html?session_id={CHECKOUT_SESSION_ID}. Treatment package success must redirect to treatment-booking.html?paid=true&package=tiny/small/medium/large/xl. These URL values unlock the correct booking pages.

Treatment Package Flow

Package Payment

  • Client only uses treatment.html after consultation and patch test approval
  • Client chooses the agreed 6-session tattoo removal bundle
  • Stripe handles the package payment outside the website
  • Stripe redirects to treatment-booking.html with paid=true and the package key

Treatment Booking

  • treatment-booking.html unlocks after the correct Stripe redirect
  • The page posts booking_type: treatment to /api
  • D1 stores package_type and amount_paid
  • Treatment bookings use the same reschedule, cancel and reminder system

Operational Logic

Front-End Structure

  • Website is the main client-facing platform
  • Consultation comes first
  • Deposit comes second
  • Booking unlocks after Stripe redirects with a valid session_id
  • Treatment packages unlock treatment-booking.html with paid=true and package type

Back-End Handling

  • Consultation Worker processes forms, file validation, PDF generation and email delivery
  • Booking API handles availability, bookings, reschedules, cancellations and admin actions
  • Cloudflare D1 stores appointment records, statuses, tokens, booking types and reminder flags
  • Reminder Worker sends 24-hour reminders and auto-completes past confirmed bookings
  • Resend sends client and internal emails
  • Private business records supports manual file storage where needed
